# 大屏开发
确保大屏在不同尺寸的屏幕上都能实现良好的适配。

## 适配方案
* rem
  - 动态设置 HTML 根字体大小，将 px 转成 rem。配合百分比或者 vw/vh 实现容器宽高、字体大小、位移的动态调整
  - 优点：布局的自适应代码量少，适配简单
  - 缺点：留白，有时图表需要单独适配字体
  + 开源项目
    - lib-flexible 早期使用
    - 作者：由于viewport单位得到众多浏览器的兼容，lib-flexible这个过渡方案已经可以放弃使用，不管是现在的版本还是以前的版本，都存有一定的问题。建议大家开始使用viewport来替代此方。

* vw/vh方案
  - 将像素值（px）按比例换算为视口宽度（vw）和视口高度（vh），能够实时计算图表尺寸、字体大小等
  - 优点：可以动态计算图表的宽高，字体等，灵活性较高，当屏幕比例跟 ui 稿不一致时，不会出现两边留白情况
  - 缺点：每个图表都需要单独做字体、间距、位移的适配，比较麻烦
  + 开源项目
    - postcss-px-to-viewport 自动转换尺寸 
    ```bash
      npm i @our-patches/postcss-px-to-viewport -D
    ```
    ```js
      // postcss.config.js
      module.exports = {
        plugins: {
            '@our-patches/postcss-px-to-viewport': {
                unitToConvert: 'px', // 要转化的单位
                viewportWidth: 1920, // UI设计稿的宽度
                unitPrecision: 6, // 转换后的精度，即小数点位数
                propList: ['*'], // 指定转换的css属性的单位，*代表全部css属性的单位都进行转换
                viewportUnit: 'vw', // 指定需要转换成的视窗单位，默认vw
                fontViewportUnit: 'vw', // 指定字体需要转换成的视窗单位，默认vw
                selectorBlackList: [], // 指定不转换为视窗单位的类名，
                minPixelValue: 1, // 默认值1，小于或等于1px则不进行转换
                mediaQuery: false, // 是否在媒体查询的css代码中也进行转换，默认false
                replace: true, // 是否转换后直接更换属性值
                include: /\/src\/views\/pc\/layoutMapBS\//,
                exclude: [/node_modules/], // 设置忽略文件，用正则做目录名匹配
                landscape: false // 是否处理横屏情况
           }
        }
       }
    ```

* scale方案
  - 根据宽高比例进行动态缩放，但是遇到一些地图或者 Canvas 中的点击事件，可能会存在错位问题，需要做针对性的调整适配。
  - 优点：相比于 vw 和 rem，使用起来更加简单，不需要对单位进行转换,浏览器的字体默认最小是不能小于 12px ，导致 rem 或 vw 无法设置小于 12 px的字体，缩放没有这个问题。
  - 缺点：留白，有事件热区偏移
  + 开源方案：
    - 原理：基于设计稿像素尺寸，通过缩放进行适配
    - [autofit.js](https://github.com/995231030/autofit.js)
    - [FitScreen](https://github.com/jp-liu/fit-screen)
