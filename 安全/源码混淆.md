# 前端代码混淆加密
在核心代码需要安全保护的情况下可以通过对源码加密混淆来增加破解难度

## 主流技术方案
* UglifyJS/Terser 
  - 最常用的压缩工具，移除空格注释，缩短变量名
* javaScript Obfuscator 
  - 功能强大的专门混淆工具
* 字符串加密
  - 将代码中的字符串转换为编码形式（Base64、十六进制等）,运行时动态解密使用
  ```js
    // 示例：Base64字符串加密
    const encodedStr = 'SGVsbG8gV29ybGQh'; // "Hello World!"的Base64编码
    const decodedStr = atob(encodedStr);
  ```

## javaScript Obfuscator 
> 是一个功能强大的 JavaScript 代码混淆工具，它通过多种转换技术将可读的 JavaScript 代码转换为难以理解和逆向工程的代码，同时保持功能不变。
* 核心特性
  - 字符串加密:将字符串文字转换为编码形式,Base64、RC4 等。运行时动态解码
   ```js
    // 原始代码
    const apiKey = "my-secret-key-123";

    // 混淆后
    const _0x12ab = ["my-secret-key-123"];
    const apiKey = _0x12ab[0];
   ```
  - 标识符混淆: 变量名、函数名重命名为无意义名称,支持多种命名生成器
   ```js
    // 原始代码
    function calculateTotal(price, quantity) {
        return price * quantity;
    }

    // 混淆后
    function _0x1a2b3c(_0x4d5e, _0x6f7a) {
        return _0x4d5e * _0x6f7a;
    }
   ```
   - 控制流扁平化:打乱代码执行顺序,使用 switch 语句或条件语句重组逻辑流
   ```js
        // 原始代码
        function checkAccess(level) {
            if (level === 'admin') {
                return true;
            } else if (level === 'user') {
                return false;
            }
            return null;
        }

        // 控制流扁平化后
        function checkAccess(_0x1234) {
            var _0x5678 = 0;
            while (true) {
                switch (_0x5678) {
                    case 0:
                        if (_0x1234 === 'admin') {
                            _0x5678 = 1;
                            break;
                        }
                        _0x5678 = 2;
                        break;
                    case 1:
                        return true;
                    case 2:
                        if (_0x1234 === 'user') {
                            _0x5678 = 3;
                            break;
                        }
                        _0x5678 = 4;
                        break;
                    case 3:
                        return false;
                    case 4:
                        return null;
                }
            }
        }
   ```
  - 死代码注入:插入永远不会执行的代码块,增加静态分析的难度
  - 调试保护: 检测开发者工具,防止代码在调试环境中运行
* 配置文件示例
  ```js
    const allObfuscatorConfig = {
        excludes: [], // 排除的 bundle 名
        enable: true, // 显示或隐藏日志输出。
        log: true,
        autoExcludeNodeModules: true, // 启用自动排除 node_modules
        threadPool: true,            // 线程池的配置
        options: {// 混淆器的选项
            // 基础配置
            compact: true,  // 将混淆后的代码压缩为一行，减小文件体积
            simplify: true, //  在混淆后简化代码结构
            log: false,     // 不输出混淆过程的日志信息

            // 控制流混淆
            controlFlowFlattening: true, // 启用控制流扁平化，打乱代码执行顺序
            controlFlowFlatteningThreshold: 1, // 对所有代码（100%）应用控制流扁平化

            // 保护功能
            selfDefending: true,  // 启用自我防御，防止代码格式化
            deadCodeInjection: false,// 不注入死代码
            debugProtection: false,  // 不启用调试保护

            debugProtectionInterval: 0,
            disableConsoleOutput: false,

            // 标识符处理
            identifierNamesGenerator: "hexadecimal", // 使用十六进制数字重命名变量/函数名
            renameGlobals: false,   // 不重命名全局变量

            // 字符串处理
            stringArray: true,// 将字符串提取到特殊数组中，通过索引访问
            stringArrayCallsTransform: true, // 转换对字符串数组的调用
            stringArrayCallsTransformThreshold: 0.5, // 50%的字符串数组调用会被转换 75%的字符串会被提取到数组中
            stringArrayThreshold: 0.75,

            // 字符串数组包装器
            stringArrayWrappersCount: 1, // 创建1个字符串数组包装器
            stringArrayWrappersChainedCalls: true, // 允许包装器链式调用
            stringArrayWrappersType: "variable", // 包装器类型为变量形式

            // 其他选项
            numbersToExpressions: false, // 不将数字转换为表达式
            splitStrings: false, // 不分割长字符串
            unicodeEscapeSequence: false, // 不使用Unicode转义序列
            ignoreImports: true, // 忽略import语句，不混淆导入
        },
    };
  ```
* 性能影响
  - 启动时间：混淆代码通常需要更长的解析时间
  - 执行速度：某些混淆技术可能轻微影响运行时性能
  - 内存使用：字符串数组和额外的函数调用可能增加内存使用
* 优化建议
  - 选择性混淆：只对关键代码进行高强度混淆
  - 渐进增强：从轻度混淆开始，根据需要增加强度
  - 性能测试：混淆前后进行性能对比测试

## Vite 库模式代码保护配置方案
1. 安装必要的依赖
  ```bash
   npm install vite-plugin-bundle-obfuscator -D
  ```
2. 配置 Vite 保护方案
  ```js
    // vite.config.js
    import vitePluginBundleObfuscator from 'vite-plugin-bundle-obfuscator';
    // 插件配置
    plugins: [
        vitePluginBundleObfuscator(allObfuscatorConfig)
    ]

  ```
