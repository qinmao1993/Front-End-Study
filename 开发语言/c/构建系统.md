# 构建系统
## Make：
  - 最经典和通用的构建工具，通过 Makefile 文件来定义构建规则。定义了一系列的规则来指定，哪些文件需要先编译，哪些文件需要后编译，哪些文件需要重新编译，甚至于进行更复杂的功能操作，
  - 无论是 C 还是 C++，首先要把源文件编译成中间代码文件，Windows 下也就是 .obj 文件，UNIX下是 .o 文件，这个动作叫做编译（compile）。把大量的 Object File 合成可执行文件，这个动作叫作链接（link）

## CMake
* 介绍
  - 目前最主流的跨平台构建系统生成器。它编写 CMakeLists.txt 文件，然后为不同平台（Make, Ninja, Visual Studio等）生成相应的构建文件。极大地简化了跨平台项目的配置。
  - CMake 本身并不直接执行编译任务。相反，它生成平台相关的构建文件（如 Makefile、Visual Studio 工程文件、Xcode 项目等），这些构建文件会交由相应的构建工具（如 Make、MSBuild 或 Xcode）来执行实际的编译工作。

* CMake 核心优势
  - 跨平台支持：生成适用于 Windows (Visual Studio)、macOS (Xcode) 和 Linux (Makefile) 的构建文件
  - 依赖管理：轻松管理内部和外部依赖关系
  - 模块化配置：支持大型项目的模块化开发
  - 自动化测试：集成 CTest 进行单元测试
  - 安装打包：提供安装和打包功能（CPack）

* 一个典型的多文件 C 项目结构如下：
  ```text
    my_c_project/
    ├── CMakeLists.txt              # 根 CMake 配置文件
    ├── include/                    # 头文件目录
    │   └── mylib.h
    ├── src/                        # 源文件目录
    │   ├── main.c
    │   └── mylib.c
    ├── libs/                       # 第三方库目录（可选）
    │   └── thirdparty/
    ├── tests/                      # 测试文件目录
    │   └── test_mylib.c
    └── build/                      # 构建输出目录（通常添加到.gitignore）
  ```

## CMakeLists.txt 示例
  ```cmake
    # CMake最低版本要求
    cmake_minimum_required(VERSION 3.10)

    # 定义项目名称和支持的编程语言
    project(my_app VERSION 1.0 LANGUAGES C)

    # 设置 C 标准
    set(CMAKE_C_STANDARD 11)
    set(CMAKE_C_STANDARD_REQUIRED ON)
    set(CMAKE_C_EXTENSIONS OFF)

    # 设置编译选项
    if(CMAKE_BUILD_TYPE STREQUAL "Debug")
        set(CMAKE_C_FLAGS "${CMAKE_C_FLAGS} -g -O0 -Wall -Wextra")
    else()
        set(CMAKE_C_FLAGS "${CMAKE_C_FLAGS} -O2")
    endif()

    # 设置包含目录
    target_include_directories(mylib PUBLIC include)

    # 自动收集源文件
    file(GLOB MYLIB_SOURCES "src/*.c")
    file(GLOB APP_SOURCES "app/*.c")

    # 创建可执行文件
    add_executable(my_app ${APP_SOURCES})

    # 链接库到可执行文件
    target_link_libraries(my_app PRIVATE mylib)


    # 查找和使用第三方库

    # 查找系统安装的库
    find_package(Threads REQUIRED)

    # 使用 pkg-config 查找库
    find_package(PkgConfig REQUIRED)
    pkg_check_modules(LIBXML REQUIRED libxml-2.0)

    # 添加包含目录
    include_directories(${LIBXML_INCLUDE_DIRS})

    # 链接库
    target_link_libraries(my_app PRIVATE ${LIBXML_LIBRARIES} Threads::Threads)

    # 设置安装路径
    install(TARGETS my_app
        RUNTIME DESTINATION bin
        LIBRARY DESTINATION lib
        ARCHIVE DESTINATION lib
    )

    # 安装头文件
    install(DIRECTORY include/ DESTINATION include)

  ```

## 使用 CMake 构建项目
1. 基本构建流程
  ```bash
    # 创建构建目录并进入
    mkdir build
    cd build

    # 生成构建系统
    cmake ..

    # 编译项目
    cmake --build .

    # 或者使用生成的构建系统（在Unix系统上）
    make
  ```
2. 指定构建类型和生成器
  ```bash
    # 指定构建类型（Debug/Release/RelWithDebInfo/MinSizeRel）
    cmake -DCMAKE_BUILD_TYPE=Debug ..

    # 指定生成器（在不同平台上）
    cmake -G "Unix Makefiles" ..        # Unix/Linux
    cmake -G "Visual Studio 16 2019" .. # Windows
    cmake -G "Xcode" ..                 # macOS
  ```
3. 常用 CMake 选项
  ```bash
    # 设置安装前缀
    cmake -DCMAKE_INSTALL_PREFIX=/usr/local ..

    # 定义自定义变量
    cmake -DUSE_FEATURE_X=ON ..

    # 显示详细输出
    cmake --verbose ..
  ```

## CMake 最佳实践
* 不要使用 file(GLOB) 收集源文件
  - CMake无法自动检测新添加的文件,最好明确列出所有源文件
* 使用现代 CMake 方法
  - 使用 target_include_directories() 而不是 include_directories()
  - 使用 target_compile_options() 而不是 add_compile_options()
  - 使用 target_link_libraries() 并明确指定可见性（PUBLIC/PRIVATE/INTERFACE）
* 正确设置依赖关系
  ```bash
    # 好：明确指定依赖关系
    target_link_libraries(my_app PRIVATE mylib)

    # 不好：全局设置会影响所有目标
    link_libraries(mylib)
  ```
* 添加测试支持
  ```cmake
    # 启用测试
    enable_testing()

    # 添加测试
    add_test(NAME my_test COMMAND my_app --test)

    # 或者使用 CTest
    include(CTest)
    if(BUILD_TESTING)
        add_subdirectory(tests)
    endif()
  ```
