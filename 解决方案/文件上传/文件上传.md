# 文件上传
文件上传是Web开发中常见的功能，它允许用户将本地文件上传到服务器。随着Web技术的发展，文件上传的方式也在不断演进，从传统的表单上传到现在的异步上传、拖拽上传等

## 传统表单上传
```html
    <form action="/upload" method="post" enctype="multipart/form-data">
        <input type="file" name="file">
        <button type="submit">上传</button>
    </form>
```

    function  validateFile(file, options = {}) {
        const {
            maxSize = 10 * 1024 * 1024, // 10MB
            allowedTypes = ['image/jpeg', 'image/png', 'image/gif'],
            allowedExtensions = ['.jpg', '.jpeg', '.png', '.gif']
        } = options;
        
        const errors = [];
        // 大小验证
        if (file.size > maxSize) {
            errors.push(`文件大小不能超过 ${maxSize / 1024 / 1024}MB`);
        }
        // 类型验证
        if (!allowedTypes.includes(file.type)) {
            errors.push('不支持的文件类型');
        }
        // 扩展名验证
        const fileExtension = '.' + file.name.split('.').pop().toLowerCase();
        if (!allowedExtensions.includes(fileExtension)) {
            errors.push('不支持的文件格式');
        }
        return {
            isValid: errors.length === 0,
            errors
        };
    }

    // 绑定父元素避免，change事件上传一次后失效

        formData.append('userId', '123');

## 文件重命名问题
* 上传的文件为什么要重命名？
  - 防止路径遍历攻击
  - 防止上传同名文件覆盖
* 有哪些解决方案
  - 简单场景可以通过添加时间戳等唯一标识的形式防止文件覆盖
  - md5重命名：基于文件内容生成的 MD5 哈希值，解决文件唯一性与内容完整性验证
  ```js
    import fs from "node:fs";
    import crypto from "node:crypto";

    const FILE_PATH = "./moment.json";
    // 计算文件 MD5
    function calcFileMD5(filePath) {
        const buffer = fs.readFileSync(filePath);
        return crypto.createHash("md5").update(buffer).digest("hex");
    }
    const md5 = calcFileMD5(FILE_PATH);
    console.log(`${FILE_PATH} => ${md5}`);

    // 1. 服务器接收文件后重新计算其 MD5，并与客户端提供的值比对，一致则说明文件在传输过程中未被篡改或损坏；不一致则可拒绝文件或提示错误，从而保证数据的正确性。
    // 2. 上传前客户端先计算文件 MD5 并发送给服务器，若服务器已存在相同 MD5 的文件，则直接返回上传成功，省去重复传输的过程
  ```

## 大文件上传
* 背景
  - 过大的文件上传容易导致浏览器内存溢出
  - 网络传输不稳定导致的重新上传问题
* 核心步骤
  - 大文件上传过程拆解后 [分片->校验->上传->合并] 四个核心步骤，每个步骤解决一个具体的问题
* 核心功能清单
  - 「大文件分片上传」：将文件切成固定大小的小片段分批上传，避免单次请求超时
  - 「秒传」：服务器已存在完整文件时，直接返回成功，无需重复上传
  - 「断点续传」：刷新页面或上传中断后，仅上传未完成的分片，无需从头开始
  - 「并发控制」：限制同时上传的分片数量，避免请求过多导致浏览器 / 服务器崩溃
  - 「手动中断」：支持用户随时停止上传，且中断后已传分片不丢失
* 完整的技术流程
  > 用户选择文件 → 前端分片+算哈希 → 校验文件状态（秒传/断点续传） → 并发上传分片 → 后端合并分片
  1. 文件分片：把大文件切成小片段，用浏览器原生 API File.slice() 按固定大小切割文件，得到多个 Blob 对象（即「分片」）
  2. 计算文件哈希：生成唯一标识
    - 用 spark-md5 库计算文件哈希，但有个关键优化：不读取整个文件，而是抽样读取部分片段（首尾分片全量 + 中间分片抽样），既能保证哈希唯一性，又能大幅提升大文件的计算速度。
    ```bash
      npm install spark-md5 
    ```
  3. 上传每个分片，并记录上传成功的分片。
  4. 如果上传中断，再次上传时先询问服务器已上传的分片，然后跳过已上传的分片，继续上传未上传的分片。
  5. 全部分片上传完成后，通知服务器合并分片。
